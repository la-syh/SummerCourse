### 2. 检查程序启动方式和模块导入

同时，AI 检查到当前 `conda ML` 环境缺少 Flask、Beautiful Soup 和 jieba，而 README 最初只列出了 Flask。AI 因此建议补充实际依赖和正确的启动说明。README 的具体修改由我完成。

### 3. 检查自动评测接口和 Flask 启动位置

课件要求提供一个能够对单个查询返回前 20 个 URL 的函数。最初版本只在 Flask 的 `/query` 路由中直接调用 `search_engine.query(key, k=20)`，没有将这一功能封装为独立接口。

AI 建议增加一个独立的搜索函数，使 Web 路由和自动评测都可以调用同一接口，并固定返回前 20 个 URL。AI 还指出，最初的 `app.run()` 位于模块顶层，其他程序导入该模块时会立即启动并阻塞 Flask 服务，因此应将服务器启动放在主程序保护中。

我根据任务需要编写了独立的 `search()` 函数，并将 Flask 启动代码放入：

```python
if __name__ == "__main__":
    ...
```

这些代码由我编写和修改，AI 仅提供了接口设计和代码组织方面的建议。

### 4. 分析在线获取标题和摘要的问题

最初版本在每次查询得到 URL 后，使用 `requests.get()` 依次访问最多 20 个网页，并从返回的 HTML 中提取标题和摘要。AI 指出，这种实现虽然直观，但存在以下问题：

- 每次搜索都需要重新访问外部网站，响应速度受网络状态影响；
- 20 个网页依次请求，每个请求的超时时间为 10 秒，最坏情况下等待时间可能很长；
- 任何一个网页超时、拒绝访问或返回错误，都可能导致整个搜索结果页面报错；
- 外部网页内容可能发生变化，展示内容与建立索引时使用的本地网页版本不一致；
- 重复查询相同结果时会重复下载相同页面，浪费时间和网络资源。

AI 建议不要在查询请求中实时联网获取元数据，而是在索引或预处理阶段直接从 Day 2 已下载的本地 HTML 中提取标题和摘要，并保存为本地元数据文件。查询阶段只需按 URL 查表，不再访问外网。

### 5. 讨论本地网页元数据的保存格式

为了给出适合现有项目的方案，AI 检查了 `downloaded_html/docID.jsonl`、本地 HTML 文件布局和 Day 1 的 `ExtractHTML.py`。当前 `docID.jsonl` 的每条记录已经保存 `docID`、原始 URL 和本地 HTML 文件路径，因此可以直接作为离线元数据提取的输入。

AI 建议新增一个 JSONL 元数据文件，每行对应一篇文档，保存以下字段：

```json
{"docID": 0, "url": "https://example.com/", "title": "页面标题", "abstract": "页面摘要"}
```

选择 JSONL 的原因是它与现有 `docID.jsonl` 的格式一致，可以逐行处理，不需要在生成时将全部文档记录同时保存在内存中。查询程序启动时可以再将其加载为以 URL 为键的字典，因为当前 Day 4 的查询函数返回 URL 列表。

AI 建议将文件保存为 `inverted_index/page_metadata.jsonl`。该目录已经在 `.gitignore` 中，因此不会将本地网页的处理结果误提交到 Git，符合课件对中间结果的要求。

### 6. 讨论标题和摘要的提取规则

AI 建议标题按照以下优先级提取：

1. `citation_title`；
2. `og:title`；
3. `twitter:title`；
4. HTML 的 `<title>`；
5. 如果以上内容都不存在，则回退为页面 URL。

摘要按照以下优先级提取：

1. `citation_abstract`；
2. `description`；
3. `og:description`；
4. `twitter:description`；
5. 如果页面没有摘要元数据，则拼接段落文本，并截取正文前 200 个字符；
6. 如果仍然没有可用文本，则保存空摘要，在 Web UI 中显示“暂无摘要”。

AI 还建议将连续空白字符合并，避免网页中的换行和缩进直接出现在搜索结果中；单个网页解析失败时应记录失败信息并继续处理其他网页，而不是终止整个元数据生成过程。

### 7. 编写离线元数据生成程序

在讨论上述方案后，我编写了 `day5/build_page_metadata.py`。该程序完成以下工作：

- 逐行读取 `downloaded_html/docID.jsonl`；
- 根据记录中的本地文件路径读取 HTML 字节；
- 使用 Beautiful Soup 提取标题和摘要；
- 对标题、摘要中的连续空白进行清理；
- 页面缺少描述时使用正文片段作为摘要；
- 单个文件处理失败时保存 URL 和空摘要，并继续处理；
- 将结果逐行写入 `page_metadata.jsonl`；
- 先写入临时文件，全部完成后再替换正式文件，避免中途中断留下不完整结果；
- 输出成功和失败的文档数量。

AI 提供了数据流设计、字段建议、提取优先级、异常回退和原子保存的参考方案。我理解方案后完成了当前代码文件，最终代码由我编写并负责。

### 8. 将本地元数据接入 Web UI

我修改了 `day5/main.py`，在 Flask 服务启动前读取 `page_metadata.jsonl`，并建立从 URL 到元数据记录的字典。搜索时仍先调用 Day 4 的检索函数获得前 20 个 URL，然后直接从字典中取得标题和摘要。

若某个 URL 没有对应元数据，当前实现使用 URL 本身作为标题；若摘要为空，则显示“暂无摘要”。因此，查询阶段不再对结果网页发起网络请求，也不会因为某个外部网站暂时不可访问而导致整个结果页面失败。

AI 同时建议使用 `Path(__file__).resolve()` 构造项目内文件的绝对路径，避免程序依赖当前工作目录。我在当前版本中使用 `PROJECT_ROOT` 统一构造 docID、倒排索引、停用词表和页面元数据路径。
